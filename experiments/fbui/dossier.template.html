What this is

The DigiLand DL7006-KB is a throwaway 7‑inch tablet built around a MediaTek MT8127. No source, no support, locked into a stale Android 7. Its one weakness: an unprotected bootloader. That crack was enough to take the whole device — dump it, boot our own Linux on it, and give it a face. The result, NEONWIRE OS, is a neon framebuffer UI drawn straight to the panel by a handful of static ARM binaries — no X, no Android, no toolkit — deployed over a single serial cable.

How it was taken — five phases

Phase A

Own the flash

Done

Attached the unprotected preloader with mtkclient and dumped the full 7.1‑GiB eMMC — a complete, hash-verified backup and a guaranteed way back from any mistake. Nothing after this is irreversible.

Phase B

Own the boot

Done

Unpacked the MTK boot / recovery / LK images, mapped every partition offset, and built custom boot images — ADB-unlocked, setup-wizard removed. We now controlled what ran at startup.

Phase C

Self-built Linux

Done

Wrapped the stock 3.18.35 kernel around our own busybox initramfs and a USB‑ACM gadget — a real root shell over serial, eMMC + SD mounts, and a writable framebuffer. A minimal Linux we own, top to bottom.

Phase D

Give it a face

Done

A from-scratch framebuffer engine (fbgfx) with a baked JetBrains‑Mono bitmap font, neon glow, panels and CRT scanlines. Two programs: neofb, a system dashboard, and neui, a touch launcher with five live panels and a working action bar — all reading real kernel state, cross-compiled static and streamed over serial to the SD card in ~2 seconds. No reflash to iterate.

Phase E

Make it the OS

Done

Embedded the UI in the initramfs so init launches it at boot — the device now comes up straight into NeonOS. Then reverse-engineered the MTK logo.bin format and flashed a neon boot splash over the vendor's. The entire boot chain, first frame to live OS, is ours.

Two hardware ghosts we exorcised

War stories
Dead touch

Taps registered internally but nothing moved. The panel is a type-A multitouch device reporting ABS_MT_POSITION frames — my release-latch stuck after the first touch. Fix: fire on the BTN_TOUCH press edge, commit on the next SYN_REPORT.

Frozen glass

The UI updated in memory but the screen sat still. The LCM is a command-mode MIPI panel — it only pushes a frame on a pan/flip, never on a plain memcpy. Fix: cycle three hardware buffers and FBIOPAN_DISPLAY every frame. (It's also why memory screenshots looked live while the panel was frozen.)

The wall we haven't broken

Honest status

Wi-Fi. The integrated CONSYS connectivity block won't power on: chip ID reads zero, its rails and bus clock never come up. The stock kernel ships with CONFIG_MODULES=n (no driver can be loaded) and there are no board sources to rebuild one; a binary power-on patch bootlooped the device. So NeonOS is, for now, gloriously offline — and it says so, in magenta, on its own network panel. wlan0 offline
